# Mimic Busters Map Kit

Unity で **Mimic Busters** のマップを自作して、ワンクリックでゲーム内を歩いて確かめられます。

このキットは、ゲームと同じマップ用コードが入った Unity プロジェクトです。マップは普通の Unity シーンとして作り、ライティングは Unity で Bake します。するとキットがマップをゲームのルールに照らしてチェックし、Windows、Linux、macOS のどれでも開ける1つのファイルにまとめ、ゲームにインストールして、そのマップでゲームを起動します。

このキットで作ったマップは、**Standard**（ゲーム内の表示は Classic。ハンターとモデラーのモードで、同じマーカーを使う派生モードのコンパニオンと Infestation も含みます）、**Practice**（ゲーム内の表示は「練習」。自由に作れて、ラウンドはありません）、**Deathmatch**（全員が武装し、陣営はありません）、**ミミックを当てろ**（キットでの表示は Guess the Mimic。1人がモデルを作り、ほかのプレイヤーが当てる、を交代で繰り返します）で遊べます。

## 必要なもの

- **Unity 6000.3.8f1**。必ずこのバージョンを Unity Hub から入れてください。マップは Unity の asset bundle で、ゲームは自分と同じ Unity バージョンで作られた bundle しか読めません。追加モジュールは不要です。キットはエディターに最初から入っている機能だけでパッケージ化します。
- マップをテストするための、Steam でインストールした **Mimic Busters**。

## はじめに

1. キットをダウンロードします。GitHub の **Code > Download ZIP** か、**Releases** にある zip を使ってください。パスの短い場所に展開します。
2. Unity Hub で **Add > Add project from disk** を選び、展開したフォルダーを選んで 6000.3.8f1 で開きます。最初のインポートには数分かかります。終わると **ようこそ** ウィンドウが開きます。ここで言語を選び（キットは英語、トルコ語、ドイツ語、スペイン語、フランス語、イタリア語、ブラジルポルトガル語、ロシア語、ウクライナ語、ギリシャ語、日本語、韓国語、中国語に対応しています）、ゲームが見つかっているか確認してください。このウィンドウは **Map Kit > Welcome** でもう一度開けます。言語はあとから **Map Kit > Settings** か、キットの各ウィンドウにある歯車アイコンで変えられます。
3. **Map Kit > New Map**。マップに名前を付け、モードにチェックを入れます。最初のマップでは **サンプルの部屋を追加** をオンのままにしておきましょう。キットが `Assets/Maps/<Name>/` にシーンを作り、ゲームに必要なものをすべて最初から配置します。マップ情報、スポーン地点、マップ境界、プローブボリューム、正しいライティング設定です。
4. **Window > Rendering > Lighting > Generate Lighting**。最初の Bake には少し時間がかかります。
5. **Map Kit > Validate**。「ゲームはこのマップを開けます。」と表示されるはずです。
6. **Map Kit > Pack and Test**。初回は **ゲーム** セクションを確認してください。キットは Steam ライブラリからゲームを探します。別の場所にある場合は **選択...** を押して、ゲームの実行ファイルを選びます。そのあと **パッケージ化してテスト** を押します。ゲームが起動し、あなたのマップで自分だけの練習セッションがすぐに始まります。

あとは自分のマップに仕上げましょう。サンプルの部屋を削除し、自分のモデルを持ち込んで、手順 4 から 6 を繰り返します。

## マップを作る

**ジオメトリ。** モデル（FBX、OBJ、Blender ファイル）とテクスチャをいつもどおりインポートして、シーンに配置します。シェーダーは Universal Render Pipeline のものを使ってください: **Lit**、**Simple Lit**、**Unlit**、**Baked Lit**。プレイヤーが上を歩いたりぶつかったりするものには、すべて Collider を付けます。動かないジオメトリは **Static** にして、Bake したライトが当たるようにします。

**マップ情報。** 新しいシーンの `Map` オブジェクトには **Kit Map Descriptor** が付いています。ゲームに表示されるマップの名前、説明、作者、モードです。シーンにちょうど1つだけ必要です。

**スポーン地点。** スポーン地点は、**Map Marker** を付けた空のオブジェクトです。その Inspector は2つのことを順に尋ねます。**1. モード** はどのゲームモードで使うか、**2. 種類** は何に使うかです。その下には、どのモードがこのマーカーを何として使うかが表示され、チェックしたモードのどれも読み取らない種類があると警告が出ます:

| 種類 | 用途 |
|---|---|
| HiderSpawn | モデラーがラウンドを始める場所（Standard）。Practice でプレイヤーが現れる場所でもあります。 |
| HunterSpawn | ハントが始まったときにハンターが出てくる場所（Standard）。準備時間のあいだ、ハンターはゲーム側のハンタールームで待ちます。 |
| LobbySpawn | ロビーに人が集まるまで全員が待つ場所。任意です。ない場合、ロビーは HiderSpawn を使います。 |
| HunterDoor | 任意。ロビーと準備のあいだは閉じたままで、ハントが始まると開くオブジェクトです。最初の1つだけが使われます。 |
| ModelerSpawn | Practice: HiderSpawn や LobbySpawn と同じく、プレイヤーが現れる場所。ミミックを当てろ: 自分の番のプレイヤーがモデルを作る場所。 |
| ArenaSpawn | 任意。1v1 の決闘の位置（Standard）。ゲームのハンタールームには専用のものがあります。 |
| GuessComputer | 任意（ミミックを当てろ）。ゲームがパソコンデスクを置く場所です。自分の番のプレイヤーはここに座り、そのモデルは ModelerSpawn に立ちます。最初の1つだけが使われます。ない場合、プレイヤーは自分のモデルの中に隠れます。 |

Standard には、HunterSpawn と HiderSpawn が少なくとも1つずつ必要です。Practice には、Practice にチェックを入れた HiderSpawn、LobbySpawn、ModelerSpawn のどれかが必要です。Deathmatch は、Deathmatch にチェックを入れたすべての HunterSpawn、HiderSpawn、LobbySpawn を使い、ほかの全員からいちばん遠い地点にプレイヤーを置きます。なので少なくとも6つ、散らばるように置いてください。「ミミックを当てろ」は、当てる側を LobbySpawn（ない場合は HiderSpawn）に、自分の番のプレイヤーを ModelerSpawn の1つに置きます。どれも「ミミックを当てろ」にチェックが必要です。その ModelerSpawn は、全員から見える場所に置いてください。どの種類も数個ずつ、散らばるように、床の上に、マップの内側に向けて置きます。マーカーから伸びる線が、プレイヤーの向く方向を示します。モードに1つもチェックが入っていないマーカーは、どのモードでも使われません。

**マップ境界。** **Map Bounds Volume** は、プレイエリア全体を囲む箱です。これを Bake すると、ゲームはプレイヤーがいられる場所を把握し、マップの外に落ちたプレイヤーを連れ戻します。箱はプレイヤーが届くあらゆる場所を覆うようにし、ジャンプや屋根のために上に余裕を持たせてください。それから **Map Kit > Bake Map Bounds** を実行します。壁、床、スポーン地点を動かしたら、そのたびに Bake し直してください。閉じたマップで、プレイエリアが箱の壁まで達していると検証で出た場合は、示された場所に穴があります。

Bake は、スポーン地点から外側に向かって、半メートルのセルで空間を埋めていきます。テレポートでしか行けない部屋は、この方法では見つかりません。その部屋の中の1点をボリュームの **Seeds** に追加し、マップの残りの部分にも1点追加してください。Seeds を入力すると、埋める処理はそれらの点だけから始まるからです。スポーン地点やテレポートの行き先が外に出てしまった場合は、検証で知らせてくれます。幅がセル1つ分しかない隙間（壁の上のすき間、足場の横の細い割れ目）は、漏れの可能性として報告されます。隙間はぴったり閉じるか、少なくとも1メートル空けてください。

**はしご。** **Map Ladder** は、プレイヤーが中にいるあいだ登れる箱です。Half-Life や Counter-Strike と同じ登り方で、はしごに向かって進むと登り、上か下を見ることで向きが決まり、横移動キーではしごに沿って横に動き、ジャンプで手を離します。空のオブジェクト（またははしごのモデル）に追加し、Scene ビューでハンドルを使って箱の大きさを合わせます。箱は、登っているプレイヤーが立つ空間です。つまり横木と、その手前の空間です。**青い矢印（Z）は、登る人が向く方向** で、はしごのほうを向きます。登る向きはオブジェクトの上方向なので、壁に立てかけたはしごなら、オブジェクトを X 軸で傾けて上端を壁側に向けます。傾きは最大 30 度です。箱の上端は、はしごの先にある床まで届かせ、迷ったら少し上まで伸ばしてください。モデル自体はソリッドでもかまいません。プレイヤーが触れる必要はありません。

**マップのバリエーション。** マップの一部をラウンドごとに違う形にできるので、ハンターはマップを丸暗記できません。空のオブジェクトに **Map Variant Group** を付け、その部分の各バージョンを、そのオブジェクトの **直接の子** にします。たとえば、開いている通路、同じ通路がふさがれたもの、3通りに積んだ木箱などです。ゲームはラウンドごとに子を1つだけオンにし、残りをオフにします。選ぶのはサーバーで、全員が同じものを見ます。**Modes** で、どのモードで選ぶかを決めます（デフォルトは Standard）。それ以外のモードでは、子はシーンに置いたままの状態になります。グループの Inspector にはバージョンが一覧表示され、それぞれに **表示** ボタンがあるので、1つずつ作って確認できます。
- **重み:** 子に **Map Variant Option** を追加すると、選ばれやすさを上げたり下げたりできます（ない場合は 1、0 なら選ばれません）。
- **Avoid Repeat**（デフォルトでオン）: ほかのバージョンを選べるあいだは、前のラウンドのバージョンは選ばれません。
- **Link Id:** 同じ ID を持つグループは同じ番号の子を選ぶので、1つのアイデアの2つの部分がそろいます。たとえば、こちらでドアが閉まっているとき、あちらで隙間が開く、といった具合です。
- グループは、別のグループのバージョンの中に入れることもできます。
- バージョンの中にあるスポーン地点は、そのバージョンがオンのラウンドでだけ使われます。
- バージョンの中にあるものには、**Occluder Static** を付けないでください。オクルージョンカリングがそれを常にそこにあるものとして扱うため、オフのラウンドでは、その後ろにあるものが消えてしまいます。検証で警告されます。

**ライティング。** 新しいマップに最初から入っているライティング設定は、そのまま使ってください: Mixed ライティングは **Shadowmask** モード、ライトマップは **Directional**、**Realtime Global Illumination はオフ** です。ゲームにはこの構成用のシェーダーしか入っていません。ライトは **Mixed** か **Baked** にします。影付きのリアルタイムライトが4つを超えると、ゲームが重くなります。フォグを使う場合は **Exponential Squared** にしてください。**Adaptive Probe Volume** は、プレイヤーとモデラーをマップに合った明るさで照らします。ほかと一緒に Bake してください（Generate Lighting に含まれます）。ジオメトリやライトを変えたら、毎回 Bake し直してください。そうしないと、ゲームには古いライトが表示されます。

**ポストプロセス。** **Volume** に載せてよいのは、色とトーンのエフェクトだけです: Bloom、Tonemapping、Color Adjustments、White Balance、Lift Gamma Gain、Shadows Midtones Highlights、Split Toning、Channel Mixer、Color Curves、Vignette。

## マップロジック

Hammer のように、マップに仕掛けを加えられます。ボタンを押すと動き出して、しばらくすると戻ってくる足場、サウンド、ダメージを与えるゾーンなどです。コードは書きません。すべて Inspector でつなぎ、処理はゲームが行います。

**Add Component > Map Kit > Logic** から追加します:

| コンポーネント | 機能 |
|---|---|
| Map Button | プレイヤーがインタラクトキーで押すボタン。Collider が必要です。押せる人、クールダウン、表示するプロンプトを設定できます。 |
| Map Mover | オブジェクトとその子を、停止点のリストに沿って移動、回転させ、上に乗っているプレイヤーも一緒に運びます。Return After: 最後の停止点に着いてから、その秒数が経つと自動で戻ってきます。PingPong と Loop は自動で動き続けます。 |
| Map Trigger | 見えない箱。プレイヤーが入ったとき、出たとき、最初の1人が入ったとき、最後の1人が出たときにイベントを出します。 |
| Map Teleport | 箱に入った人を行き先のオブジェクトへ送り、そのオブジェクトと同じ方向を向かせます。 |
| Map Hurt Zone | 中にいる人に一定間隔でダメージを与えるか、即死させます。マップによる死亡は、誰のスコアにもなりません。 |
| Map Sound | その場所で鳴るサウンド。1回だけかループか、距離で小さくなるかどこでも同じ音量かを選べます。 |
| Map Effect | ゲームに入っているエフェクトの1つ: 煙、蒸気、火、火花、ほこり、しずく。色、大きさ、量を設定できます。 |
| Map Toggle | オブジェクトとその子（描画、当たり判定、ライト）を表示または非表示にします。 |
| Map Relay | 1つの入力を複数の出力に渡します。出力ごとに遅延を設定できます。 |
| Map Timer | 有効なあいだ、一定間隔でイベントを出します。 |
| Map Counter | カウントし、目標の値に達したらイベントを出します。 |
| Map Round Events | ラウンド開始、ハント開始、ラウンド終了。 |

**つなぎ方。** どのコンポーネントにも **出力** のリストがあります。各出力は、*イベント*（Pressed、ArrivedAtEnd、Entered...）、*ターゲット*（ドラッグして入れる別のロジックコンポーネント）、*入力*（Forward、Back、Play、Enable、Disable...）、*遅延*、そして入力が数値を取る場合はその数値（停止点の番号、量）でできています。Inspector には、そのコンポーネントが出すイベントと、ターゲットが受け付ける入力だけが表示されます。動かない接続はオレンジ色で示され、その下には、このコンポーネントにつながっているものが一覧表示されます。**Map Kit > Logic** では、すべての接続を1ページで見られます。

例: ボタンの *Pressed* イベントを、リフトの *Forward* 入力につなぎます。リフトには停止点が1つ（1.8 m 上）あり、Return After は 4 です。押すと上がり、4秒後に下りてきます。**New Map** のサンプルの部屋にはちょうどこれが入っていて、さらにモーター音（リフトの *Started* を Map Sound の *Play* へ）と、もう1つの部屋にはヒーターもあります。1つのボタンで、Map Hurt Zone と炎の Map Effect を同時に切り替えます。

**連鎖のきっかけになったプレイヤー。** プレイヤーが起こしたイベント（押す、トリガーに入る、ダメージを受ける）は、遅延も含めて、連鎖全体を通してそのプレイヤーを覚えています。そのプレイヤーに作用する入力は2つあります。ダメージゾーンの *HurtActivator* は、そのゾーンのダメージを1回だけ（または出力の数値の分を）与え、テレポートの *TeleportActivator* は、そのプレイヤーを行き先へ送ります。押した人だけを下に落とす落とし戸のボタンや、踏み込んだ人だけにダメージを与えるトリガーも、つなぐだけで作れます。箱は要りません。この使い方だけをするテレポートは、無効の状態で始めてください。そうしないと、テレポート自身の箱でも人が送られてしまいます。

**パッケージ化する前に確かめる。** Scene ビューでは、各出力の線にイベントと入力の名前が表示されます。Map Mover を選ぶと、各停止点にハンドルが表示され、「プレビュー」の下には半透明のコピーが出ます。このコピーは経路に沿ってスライドさせたり、ゲームと同じように再生したりでき、移動にかかる時間も表示されます。

ラウンドが始まるたびに、すべてが作ったときの状態に戻ります。Start Enabled がオフのコンポーネントは、*Enable* 入力が届くまで何もしません。

**注意点。**

- 動くものは **Static** にしてはいけません。static batching でその場に固定され、Bake したライトも元の場所に残ってしまいます。動くものはプローブが照らします。
- 動く足場は、行く手にいるプレイヤーを押します。押せないときは **When Blocked** の設定に従い、引き返す、押しつぶす、そのまま進む、のどれかを行います。
- 動く足場から跳んだプレイヤーは、着地するまで足場の横方向の速度を保ちます。なので、動いている渡し船の上でジャンプすると、渡し船の上に着地します。
- テレポートの行き先は、スポーン地点と同じようにチェックされます。そこに固体がなく、下に床があることが必要です。行き先がテレポート自身の箱の中にあると、1秒後にプレイヤーがまた送られてしまいます。検証で警告されます。
- サウンド: 1つにつき最大 2 分、モノラルかステレオ、48 kHz まで。1つのマップのサウンドは、合計でメモリ上 32 MB まで。長いサウンドは **Compressed In Memory** か **Streaming** で読み込んでください。サウンドには、プレイヤーの効果音の音量設定が適用されます。
- 遅延のないループ（A が B を、B が A を同時に起動する）は、ゲーム内では 32 ステップで打ち切られ、検証ではエラーになります。ループ内の出力の1つに遅延を付けてください。このようなループになるのは、ターゲットをその場ですぐ動かす入力だけです（押す、リレーのトリガー、カウンターの変化、どこかへ送られる Mover）。自分自身をオフにするボタンや、終わるともう1曲を始める曲は問題ありません。
- 上限: ロジックコンポーネントは 256 個、1つにつき出力は 16 個まで、マップ全体で入力は1秒あたり 200 回まで。

**試してみる。** 「パッケージ化してテスト」では、マップは練習モードで開きます。ハンターもモデラーもいません。開発者コンソールで `maprole hunter` か `maprole hider` を使うと、ロールによる絞り込みを試せます。`maplogic` はすべてのコンポーネントの状態を一覧表示し、`mapfire <number> <input>` は入力を手動で送ります。

### サンプルマップ: Logic Playground

**Map Kit > Examples > Logic Playground** は、すべてのロジックコンポーネントが動いているグレーボックスのマップを `Assets/Maps/LogicPlayground/` に作ります。聞かれたらライティングを Bake し、ほかのマップと同じように「パッケージ化してテスト」で試すか、オブジェクトを開いてつなぎ方を見てください（**Map Kit > Logic** ですべての接続を一覧できます）。色で役割がわかります。グレーはワールド、オレンジは押すもの、黄色は動くもの、赤はダメージを与えるもの、青はテレポート、紫は現れたり消えたりするものです。天井は見えません。何も描画しない Collider で、マップ境界の Bake のために、屋根のない中庭を閉じています。

9つの部屋が 3×3 のグリッドに並び、全体の幅は 36 m です。全員が真ん中の部屋からスタートします。

| 部屋 | 内容 |
|---|---|
| 00 Hub（中央） | Map Round Events: ラウンド開始時にチャイム。ハント開始時にサイレンと赤い煙のビーコン。ラウンド終了時に花火（遅延を付けて火花とサウンドを鳴らすリレー）。最初からループでうなり続ける発電機。 |
| 01 Doors（南） | 開いてから4秒後に自動で閉まり（Return After）、誰かがじゃまだと引き返して、ブザーを鳴らすスライドドア。その手前にあり、ハンターが来るとボタンを押してくれるトリガー（Press）。どちらのボタンでも開け閉めできる開き戸（Reverse）。 |

## ルール

ゲームは、Unity にマップを開かせる前にマップを読み込み、これらのルールから外れるものはすべて拒否します。**Map Kit > Validate** はエディター上でこれらをすべてチェックし、**Pack and Test** はパッケージ化したファイルを、ゲーム自身のコードでもう一度チェックします。

- **コンポーネント:** Mesh Filter、Mesh Renderer、LOD Group、Box、Sphere、Capsule、Mesh の各 Collider、Light、Reflection Probe、Light Probe Group、Occlusion Area と Portal、Adaptive Probe Volume、Volume、キット独自のコンポーネント（Map Marker、Map Mode Object、Map Bounds Volume、Penetrable Surface、Probe Volume Region、Kit Map Descriptor、Map Ladder、Map Variant Group、Map Variant Option）、そしてマップロジックのコンポーネント。自作のスクリプトは使えません。カメラ、オーディオソース、パーティクルシステム、UI、動画、テレイン、アニメーション、物理ボディも使えません。サウンドとエフェクトは Map Sound と Map Effect で入れます。
- **シェーダー:** Universal Render Pipeline の Lit、Simple Lit、Unlit、Baked Lit。空は Skybox の Procedural、Cubemap、6 Sided、Panoramic。
- **レイヤー:** Default、Ignore Raycast、MapBlocker（見えない壁）、GuessMapBlocker。
- **ライティング:** 上記のとおり。ライトは最大 64 個。
- **サイズ:** パッケージは最大 256 MB、テクスチャは 512 MB、テクスチャの長辺は 8192 ピクセル、三角形は 300 万、頂点は 600 万、レンダラーは 10,000 個まで。
- **名前:** マップの ID は、シーン名を小文字にしたものです。使えるのは英字、数字、`-`、`_` で、23 文字まで。ゲーム自身が使っているシーン名（Startup、Menu、Game、HunterRoom など、および `Map_` や `GameMode_` で始まるもの）は使えません。

エラーは、ゲームがそのマップを開かないことを意味します。警告は確認しておく価値がありますが、マップが開けなくなるわけではありません。

## フレンドと遊ぶ

セッションの全員が、まったく同じマップファイルを持っている必要があります。ゲームはマップを読み込む前にファイルを比較します。パッケージはどのシステムでも同じなので、マップを一度パッケージ化したら、キットの `Builds/Maps/<id>/` にあるフォルダーを（zip にして）フレンドに送ってください。受け取った人はそれぞれ、そのフォルダーを変更せずに、ゲームのマップフォルダーに入れます:

| システム | フォルダー |
|---|---|
| Windows | `%USERPROFILE%\AppData\LocalLow\DevAdam\MimicBusters\Maps\Local\` |
| macOS | `~/Library/Application Support/DevAdam/MimicBusters/Maps/Local/` |
| Linux | `~/.config/unity3d/DevAdam/MimicBusters/Maps/Local/` |

結果は `...\Maps\Local\<id>\map.json` のようになり、その隣に `map.any.bundle` があります。これでマップが、ゲームのマップ選択の **コミュニティ** に表示されます。Steam ワークショップへの対応は、今後ゲーム内からできるようになる予定です。

## うまくいかないとき

- **ゲームがマップを拒否するとキットに表示される。** 理由は「パッケージ化してテスト」ウィンドウに一覧表示されます。完全なレポートは Console と `Builds/Maps/<id>.report.txt` にあります。
- **マップを開けなかったとゲームに表示される。** ゲームで **設定 > ゲームプレイ > 開発者コンソール** をオンにし、Esc の下にあるキーでコンソールを開いて `kitmaps` と入力します。自分のマップと、プレイできないマップがあればその理由が一覧表示されます。`kitinspect <id>` を使うと、マップを読み込まずに中身を読み取れます。
- **マップが暗すぎる、またはライトがおかしい。** ライティングを Bake し直してから、もう一度パッケージ化してください。シーンが別のシーンのライティングデータを使っていると検証で出た場合は（コピーしたシーンで起こります）、**Map Kit > Tools > Detach Copied Lighting** を実行してから Bake します。
- **プレイヤーが床をすり抜ける、または壁の中にスポーンする。** Collider を確認し、スポーン地点を動かして、マップ境界を Bake し直してください。
- **古いキットで作られたマップだとゲームに表示される。** 新しいキットをダウンロードし、そのキットでマップを開いて、もう一度パッケージ化してください。
